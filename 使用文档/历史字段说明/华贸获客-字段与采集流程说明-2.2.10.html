本版处理了什么

2.2.10 修复关注私信确认执行后的反馈、可见浏览器复用、主页按钮定位、会话原生填写、两类 UID 回执匹配和未点击误记待核验。只对抖音浏览器操作保留完整间隔，内部检查和本地填写不重复等待。

作品真实标题与正文分开保存，再合成为统一的“视频描述”。线索库根据作品 ID 关联中央作品记录，作品描述后来补齐时，旧线索的显示、AI 输入与导出也能读取最新内容。

采集历史和线索库提供“查看全文”；名称下的“查看作品”可直接打开完整作品文字。主字段固定置前，四类补充字段按组选择，保持 16px 正文和高对比显示。

文档生成不会检查已安装客户端版本，也不会执行安装。已有作品记录的文字可关联补齐显示；原来完全没有取得的文字，需要新版本继续采集或强制重采。请以当前客户端版本和实际升级记录为准。

从作品链接到触达的完整流程

输入链接→采集响应→AI 判断→筛选与预检→固定名单→同主页关注 / 私信→核验结果
  1. 启动自动检查：先登录软件授权账户，每次进程启动会顺序检查已有抖音账号。各账号使用自己保存的专用 Chromium 资料；需要时临时在后台读取本人页面和真实响应，用完关闭临时窗口。已有窗口只原地检查，不跳转或关闭。现有任务运行时等待；停止或退出会取消检查。账号管理显示检查进度和已登录、未登录、待确认、需验证等状态；上次保存的已登录仅作历史，没有可靠响应不冒充成功。
  2. 准备账号：新增或未登录账号需打开对应账号浏览器，扫码并在手机确认；“检查”仍可手动重新核验。软件授权与抖音登录分别判断，检查不做关注、私信或用户主页补全。
  3. 浏览器启动：优先使用已安装的 Chrome / Edge（含常见的 32 位 Edge）；没有系统浏览器时，直接按随包清单定位安装目录内的 Chromium，外部 Playwright 缓存不影响查找。点击打开登录会激活账号页面，后台检查窗口不作为可见登录窗口复用。启动失败在账号状态和操作日志显示文件缺失、资料占用、目录权限、进程启动或系统不支持等明确类别与错误码。
  4. 输入作品：支持完整分享文本、v.douyin.com 短链接、/video/ 和 /note/。解析后按作品 ID 去重；保留图文路径。强制重采只针对明确勾选的输入组。
  5. 采集作品文字：先监听后导航，只处理目标作品详情与页面结构化资料。作品 ID 对不上、响应失败或字段未返回时，不用相关推荐填补。
  6. 打开评论并翻页：视频评论区已显示时直接读取；图文先切换到“评论”。滚到真实评论容器底部，让网页生成下一页请求；不滚相关推荐，也不自行拼接带签名的接口 URL。
  7. 核验每页：只接收目标作品、status_code 明确成功的评论响应。cursor 或新评论 ID 推进分页；同一条评论重复出现时补齐真实资料，不重复新增。旧响应不回退游标；有效 has_more=0 才确认一级评论分页结束。达到轮数上限、停止或异常保留部分结果和续采状态。
  8. 判断可联系范围：关键词只作简单筛查。单条、批量和匿名样例共用一份启用预设，结果仅为“是 / 否”及最多30字符理由。“是”表示业务相关、可考虑联系，不等于确定需求；明确无关、广告、拒绝、已解决或明确不需要为“否”。规则或作品文字变化后，旧结果需要重判；接口失败与旧待确认不会自动变成“是”。
  9. 筛选进入任务：预检读取当时线索库完整筛选结果或已勾选编号，生成固定账号、用户名单和动作计划。页面最多展示最近 500 条，不代表完整筛选任务仅执行 500 条。确认后只执行冻结名单；后续筛选变化仅用于下一次预检。
  10. 按用户处理：确认执行后立即显示启动反馈，并定位任务进度。启用对应账号的可见浏览器，同一次主页访问完成已返回资料回填、需要的关注及私信。通过浏览器原生点击和填写操作唯一的主页按钮与当前会话；目标变化或控件有歧义时停止或明确记录未执行。跳过和等待原因显示在进度和日志中。
  11. 间隔范围：访问主页、关注、打开私信会话及实际发送使用统一浏览器操作间隔。内部检查、控件准备和本地填写不再额外等完整间隔；仍检查工作时段、定期休息、授权和停止。间隔未到等待下一操作，不因此漏掉名单用户。
  12. 明确记录结果：结果分别为确认成功、确认失败、待核验。找不到按钮且没有点击是本次确认失败，不扣关注或发送尝试、不留下待核验锁。点击前保存待核验，避免点击途中进程退出后重复操作。关注响应分别核对主页 sec_uid 与数字 UID；已关注的网页状态只保护性跳过，不伪造本次成功。未知私信协议仍需人工核验，不能自动当成功或重发，也不因正常待核验就触发连续异常暂停。真正的页面限制、操作错误及异常仍暂停。
  13. 贯穿业务任务：采集、AI判断和触达的对外尝试经统一调度，操作前检查授权、工作时段和停止状态，连续异常暂停。启动账号检查也逐步检查授权和停止状态；它只读取登录反馈。停止按钮在等待、休息和授权失效时均保持可用。

翻页使用“网页触发＋响应采集”。加上鼠标轨迹不能证明更安全，也不能保证账号不会受限；本版不为了“像真人”另增无意义点击。操作间隔可以缩短，但仍等待本页响应、检查异常并尊重停止。

AI 请求、字段与批量判断规划

本版核对发现：旧版每批3000字符预算重复计入每条作品描述，实际请求又重复固定上下文；较长图文容易被拆成单条。旧提示词和返回格式要求三值、评分、长理由，与当前获客判断标准不同。新版本采用下列统一合同。

一份介绍和要求，多条独立线索

系统消息只放一次公司业务、目标客户、明确需求、容易误判、启用提示词、固定判断政策及返回要求。用户消息为编号线索；同作品描述写入共享作品数组，每条线索引用作品编号。编号 i 是本批位置，同一UID有多条评论也分别判断，不按昵称或UID把结果写入另一条记录。

强制回执与入库字段

回执只接受 JSON 数组，每项恰好包含 i、need、reason。need只能为是或否，reason为1至30字符；禁止评分、待确认、额外字段、漏项、重复编号和越界编号。

按容量的90%顺序装批

  1. 先经授权与调度读取选中模型的 /models 容量：context_window含输入和输出，max_output_tokens限制一次返回。
  2. 先计公司介绍、启用规则、最终要求和消息包装；然后按当前固定范围顺序，逐条加入评论和必要作品上下文。同一作品只写一次。
  3. 完整输入与返回结果预留一起保持在模型上下文的90%以内，输出预留也不能超过模型输出限制。token按UTF8字节加消息开销保守估算；这是估算，不是精确分词数量。
  4. 加下一条将超预算时，发送当前批次；校验回执并回填后，再处理下一批。自动模式不按旧3000字符或20条提前切批。
  5. 单条仍放不下时记录原因并保持未判断，不强行发超限请求；介绍本身超限时直接提示调整。
  6. 截断或不合合同的回执不能当成功。缩小批次重试，每次仍检查授权、停止和连续异常；可保留单条兜底。统计使用服务器usage返回的实际用量。

官方依据（核对日期2026-10-08）：模型容量、输入输出与截断规则、字符与token换算。容量会变化，运行时优先读实际模型接口。

保存和阅读

原始 item_title / itemTitle、desc、caption 保存到 workRawText；真实标题为 workTitle，完整正文为 workContent，标题与正文去重组合为 workText。主字段“视频描述”统一读取组合后的全文。

视频和图文都适用。标题没返回就留空，不用正文第一行假造标题；图片内的文字不等于平台 desc。本版不做图片 OCR，也不编造平台未返回的内容。

列表显示摘要，全文弹窗保留换行、可滚动、可复制。剪贴板不可用时明确提示 Ctrl+C，并选中原文。

AI 上下文

作品文字不超过 12000 字符时完整发送；超过时保留适合预算的真实标题及正文开头、末尾，中间附明确省略标记。正文可用预算约 75% 给开头、25% 给末尾，过长标题按正文一起处理。

AI 同时收到 workContext.truncated、原文长度、输入长度、来源与全文摘要校验。提示词禁止推断被省略部分；业务相关但需求未明可判是，理由明确说明，不能伪称确定需求。这只控制 AI 请求预算，不删本机原文。

缺失描述与平台明确空文字分别记录。“描述待补充”意味着尚未取得真实文字，“作品无文字描述”意味着平台已明确返回空文本。

Excel 单表分组与完整长文本

导出文件只有 获客线索 一个页签。上方每行一条评论线索，按主要字段、基础信息、视频与图文、评论信息、用户信息横向分组；冻结前四行与前四列，筛选范围只包含线索。UID、sec_uid、作品 ID 与评论 ID 保持文本格式。下方独立“作品资料”区域保留全部作品及上次采集时间、采集次数，包括尚无线索的作品。作品信息按作品 ID 关联，不按行号拼接。

单元格超过 32767 个字符或 253 个换行时，主表仅放摘要和全文位置，原文分段写入同一页签下方“完整文本”区域。按记录类型、编号、字段 key 和分段序号定位全文；每段限制 30000 字符及 250 个换行，并检查 Excel 编码长度。“完整内容分段”列供阅读；“完整内容JSON”列逐段 JSON.parse 后按分段序号拼接，可精确恢复 CRLF、反斜杠、控制字符与 Unicode，不受 Excel 特殊转义影响。不要把主表摘要误当作已删除正文。

本轮已保存图片数量与平台作品类型；全套图片链接和图片 OCR 尚未加入字段表。它们可以按后续真实响应扩展，当前不会把未实现能力标成已采集。
