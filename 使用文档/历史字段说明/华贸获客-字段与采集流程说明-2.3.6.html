外部与内嵌浏览器可切换，保留原有业务数据

本版默认使用外部专用浏览器，优先恢复原有账号运行方式。账号管理新增“浏览器模式”，每个账号可独立选择外部或内嵌。采集、关注与私信共用原有流程，仍由 Playwright 操作控件并观察对应页面响应。内嵌扫码后“访问太频繁”的实网问题尚未确认修复，当前提供外部模式作为兼容选择。

升级保留 API Key、设置、账号列表、线索、联系记录和旧 chrome-profiles；新的 electron-profiles 使用独立内核，各账号首次需要重新扫码，不自动复制 Chrome 登录状态，也不需要删除或重建账号。外部模式继续读取 chrome-profiles；首次使用内嵌才需要在独立资料中重新扫码。切换不会复制 Cookie，不会删除任一模式的数据。

继续逐个用户核对关注关系与可读私信历史

本版在每位用户主页核对当前关注关系；已关注则跳过，旧关注记录不替代本次网页响应。进入目标对话后检查可读历史，含手动发送的出站文字；明确历史与本地跨账号记录合并，遵从本次预检查冻结的重复联系规则。网页历史不计本次发送成功。网页历史无法确认且本地无已发或待核验时，按用户要求静默首发，不弹提示、不保存未知观察。

继续支持主页私信入口点击后停在消息列表、列表行没有 UID 的情况。在主页昵称仍与入口点击时捕获的一致时，用完整昵称唯一匹配活动列表的目标行，绑定真实元素点击一次。之后继续核对活动聊天头昵称，不选首行；昵称相同的多个候选不自动选择，头像和聊天 UID 不参与核对。沿用就绪检查，不新增额外固定间隔。每次真实界面操作前重新检查授权与停止，入口、消息列表、目标会话和发送控件分别给出未发送原因。

线索主表采用7列、15px正文和两行摘要；评论后紧接作品，日期与时间分行，主页改为复制入口。AI分成全部、未判断、AI是、AI否和待重判，联系状态单独筛选；支持评论近1天、3天、一周与全部，以及当前筛选、已勾选或全部线索导出。

2.3.6 把主要工作整理为“账号就绪 → 采集评论 → AI 与名单 → 关注与私信 → 结果核验”。总览给出下一步入口；每个业务页面只保留当前任务的输入、主要按钮和进度，任务上限等规则收进展开区，三组节奏集中在设置页面。

评论翻页3秒±40%，作品之间10秒±20%，用户之间10秒±40%。同一用户主页内连续完成需要的关注、私信、填写和发送。仅等待真实页面、控件与响应就绪，不再给每个动作添加一段等待。原来每一步的间隔设置已替换为这三处节奏。

采集正常结束后默认自动批量判断本次评论用户，包含本次回填的已有记录；作者和空评论不参与，不按关键词提前排除。已有效判断的记录跳过；停止、采集异常不会自动接着AI，缺少API设置时评论仍保留。

联系前一次预检查冻结账号、去重用户名单、逐人动作、消息预览及重复联系开关和间隔。执行页面逐步显示“主页 → 关注 → 打开私信（含选择会话与检查历史） → 填写 → 发送 → 核验”；明确区分没有发送与已经点击发送但待核验。全过程保留授权、停止、目标校验和连续异常保护。

文档生成不会检查已安装客户端版本，也不会执行安装。已有作品记录的文字可关联补齐显示；原来完全没有取得的文字，需要新版本继续采集或强制重采。请以当前客户端版本和实际升级记录为准。

账号浏览器与运行方式

  1. 在“账号管理”选定账号及浏览器模式，点“打开登录”。默认外部模式显示专用浏览器窗口；内嵌模式显示在“账号浏览器”中。标签只切换已打开的内嵌账号，不能替代开户或授权。
  2. 每个账号首次使用新版内嵌浏览器时重新扫码，并在手机确认。旧 Chrome 浏览器资料仍在原数据目录，未删除、未改写；新内核不承诺继承旧 Cookie。
  3. 上方账号标签用于切换页面；网址仅显示与复制，不提供任意地址输入。后退、前进和刷新作用于当前内嵌账号；返回工作台回到先前业务页。普通加载与网址状态更新不会抢走正在操作的业务页。
  4. 切到其它业务页、打开弹窗或出现登录遮罩时，暂时隐藏内嵌视图。隐藏不等于停止任务、关闭账号或退出登录；需要暂停所有动作请点全局“停止所有任务”。内嵌网页范围会随布局更新，不能覆盖全局停止。

内嵌协议、导航拦截与后台渲染

本节供后续开发交接使用。原有采集、关注与私信代码仍经生产 Playwright 连接访问当前账号页面；host 的协议兼容应保持账号和目标边界，不能只让测试替身返回成功。

独立页面会话生产host支持Playwright newCDPSession(page)所需的独立页面CDP会话，仍只允许当前账号的target及所属会话；独立会话按父会话和代次绑定，分离时不影响主页面会话，也不能附着到另一账号
逐跳导航校验collection-browser通过独立会话的Fetch.requestPaused在主框架Document请求和响应阶段逐跳核对允许的HTTPS域名、GET导航、授权及停止；限制跳数，校验Location后在同页继续。停止或异常先终止挂起请求再释放会话，不以兼容CDP为由扩大导航权限
隐藏页面问题隔离复现中隐藏账号页的输入框聚焦后可降至约1fps，即使backgroundThrottling关闭也可能拖慢真实控件就绪
持有范围Runtime.callFunctionOn / DOM.scrollIntoViewIfNeeded / Input.*；上述CDP命令存续期间，按当前账号引用计数持有beginFrameSubscription(true, 空回调)；重叠命令共用订阅，正常完成或异常在finally释放，账号关闭也释放，最后一个持有者退出时endFrameSubscription
图像处理空回调丢弃帧图像，不保存、不记录、不向后台或远端转发图像；仅当前账号WebContents，不采集整个桌面
空闲及任务节奏命令之间没有常驻帧订阅或采样；保留原页面requestAnimationFrame与输入事件，不改任务等待间隔，不额外重试click

导航授权租约与原生渲染租约分别处理不同问题：前者使手动后退、前进、刷新与任务互斥；后者只在指定协议命令执行期间保持页面所需的渲染。它们不更改业务的评论翻页、作品或用户间隔，也不会将一次发送点击重复执行。

隔离验证覆盖隐藏视图、聚焦后空闲再点击、并发命令及异常/关闭释放；隐藏测试不等同于已完成所有系统的最小化完整流程验证，也不证明真实平台全部布局或发送均通过。真实 host、client 与 engine 的整流程隔离验证记录于 build-tools/verify-embedded-outreach.js，页面和响应均为本机合成样例，并非真实平台发送记录。源码及验证脚本摘要由本次构建重新生成。

2.3.4：只核对完整昵称

已复现旧版误暂停：某些头像地址不含 aweme-avatar 路径，被旧规则误判无效。按用户最新要求，当前 StackLayout 会话只比较目标主页昵称和活动聊天顶部昵称，不再读取头像或要求聊天 UID，也不等待头像加载。

只点击目标主页内的私信入口。网页可能先出现消息列表，再自动进入聊天；聊天已就绪时直接继续。停在列表时，只点击与主页完整昵称一致的唯一会话行一次；多个同名候选不选择，不选首行。进入聊天后再次核对顶部昵称，消息列表中的名字不能代替当前聊天标题。

文字和图片表情按原顺序读取，支持纯表情昵称；长昵称读取 DOM 中的完整文字，不受视觉省略号影响。主页或聊天昵称变化、缺失时保持未发送。输入框、停止操作、历史防重、发送回执检查继续保留；昵称相同不代表平台 UID 认证。本轮隔离验证不代表所有实网布局已验证，也不代表向真实账号发送成功。

“AI 是”和“AI 否”只包含当前有效结果：已完成判断、结果为是/否、理由为1至30字符，且规则版本与完整输入摘要都匹配当前内容。历史结果、缺少有效性证据或内容改变的结果进入“待重判”；从未有判断结果的记录进入“未判断”。分类数量受搜索、评论时间和联系状态等其它筛选影响，只忽略当前 AI 分类。

联系状态单独选择全部状态、暂无联系记录、有关注记录、已有私信记录、待核验、操作失败、不再联系或已回复。已有私信记录包含本软件确认结果及明确网页历史；列表分别显示“私信已确认”和“历史已私信”，网页历史不增加成功次数。关注观察必须属于当前账号，其他账号旧复制的关注待核验不影响本账号分类。待核验优先于已有记录，即使曾有成功次数也不能替代本次结果核验。AI 分类和联系状态不会互相覆盖；当前有效的 AI 是仍须经过任务预检查。

评论时间：全部、1天、3天、一周

同一用户可能归并多条评论；时间筛选对应当前线索主评论的 ID、正文和时间，不用补充评论的时间冒充主评论时间。预检查在开始筛选时固定截止时间，再冻结执行名单，等待过程不会滚动扩大或缩小本次范围。

从作品链接到触达的完整流程

输入链接→采集响应→AI 判断→筛选与预检→固定名单→同主页关注 / 私信→核验结果
  1. 启动自动检查：先登录软件授权账户，每次进程启动会顺序检查已有抖音账号。各账号按所选模式使用独立浏览器资料：默认外部 chrome-profiles，可选内嵌 electron-profiles。后台读取当前账号页面和真实响应，两种模式的登录证据互不沿用。临时检查按生命周期关闭，已有账号页面只原地检查，不跳转或关闭。现有任务运行时等待；停止或退出会取消检查。账号管理显示检查进度和已登录、未登录、待确认、需验证等状态；上次保存的已登录仅作历史，没有可靠响应不冒充成功。
  2. 准备账号：新增或未登录账号需打开对应账号浏览器，扫码并在手机确认；“检查”仍可手动重新核验。软件授权与抖音登录分别判断，检查不做关注、私信或用户主页补全。
  3. 浏览器启动：账号管理可逐账号选择外部专用浏览器（默认）或内嵌浏览器。外部模式沿用原 chrome-profiles，优先系统 Chrome、其次 Edge、最后随包 Chromium，通过 Playwright 启动专用窗口。内嵌模式由 Electron WebContentsView 承载账号网页，使用独立 session，后台通过进程 IPC 与带随机会话凭据的本机回环桥接接入 Playwright。没有裸 remote-debugging-port，网页不能调用桌面管理 IPC。点击打开登录按所选模式显示专用窗口或内嵌页面；内嵌模式切换工作台只是隐藏视图。更换浏览器模式须先停止任务；关闭旧上下文成功后才保存新模式，并清除上一模式的登录显示，重新检查。切换不删除 API、线索、联系历史及任何浏览器资料。启动失败显示具体反馈，不能靠删除账号资料试错。
  4. 输入作品：支持完整分享文本、v.douyin.com 短链接、/video/ 和 /note/。解析后按作品 ID 去重；保留图文路径。强制重采只针对明确勾选的输入组。
  5. 采集作品文字：先监听后导航，只处理目标作品详情与页面结构化资料。作品 ID 对不上、响应失败或字段未返回时，不用相关推荐填补。
  6. 打开评论并翻页：进入视频或图文后找到真正的评论区域；需要时切换到“评论”。首屏评论就绪后，以3秒±40%（1.8～4.2秒）节奏滚到评论容器底部，让网页请求下一页。响应处理与间隔共用同一时间窗口；响应慢时不再额外加完整间隔。只等待目标评论响应，不滚相关推荐，也不重放带签名的接口URL。作品处理结束后，仅在进入下一个实际作品前等10秒±20%（8～12秒）；单作品结束不空等。
  7. 核验每页：只接收目标作品、status_code 明确成功的评论响应。cursor 或新评论 ID 推进分页；同一条评论重复出现时补齐真实资料，不重复新增。旧响应不回退游标；有效 has_more=0 才确认一级评论分页结束。达到轮数上限、停止或异常保留部分结果和续采状态。
  8. 自动判断本次评论用户：正常采集结束后，服务端直接串接批量AI，只取本次实际评论响应涉及的记录，包含已有线索的本次回填；按线索编号去重，排除作品作者与空主评论，不按关键词先筛除。当前有效结果跳过，仅判断未判、旧规则或内容已变化的记录。停止、异常或每日上限导致采集中断，不会自动启动AI；缺少API Key或未启用AI时，已采集评论仍然保存，页面提示先补设置，再判断本次范围。AI给出“是/否＋不超过30字符理由”，“是”需有评论者求助、服务咨询或本人/朋友当前问题，不等于确定需求或购买。
  9. 筛选进入任务：在“AI 与线索”核对结果，选择当前完整筛选范围或勾选记录。预检查按执行账号和用户去重，冻结用户名单、每人的关注/私信动作、话术模板及消息预览；先看清每人将发送什么，再确认。页面最多显示最近500条，完整筛选任务不限这500条。后续筛选变化仅用于下一次预检查，已冻结的身份或相关配置变化会拒绝旧计划。
  10. 按用户处理：确认后打开执行账号的可见浏览器，进入名单用户主页，同一次访问完成已返回资料回填、需要的关注、打开目标私信、填写和发送。已经关注的用户直接做需要的私信；已经私信过的用户默认只补关注。页面、控件与会话就绪即继续；不会因前一种动作的旧间隔而跳过后一种动作。目标身份变化或控件有歧义时，明确暂停或记录没有执行。私信入口可能先打开消息列表；列表缺少 UID 时，在已捕获且当前一致的主页昵称约束下，用完整昵称唯一匹配活动目标行，绑定原生点击一次。多个同名候选不选择，不选首行；之后仍检查活动聊天头，不能把列表出现当作目标会话已确认。
  11. 用户切换：当前实际访问用户处理结束后，进入下一实际用户之前等待10秒±40%（6～14秒）。同一个用户主页内不另设动作间隔。无需访问的跳过用户不启动一轮等待，最后一个用户处理完立即结束。关注和发送的回执确认、页面与控件就绪采用有限时等待，不是每一步固定睡眠。
