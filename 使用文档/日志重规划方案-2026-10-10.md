### 1.5 隐私与脱敏现状（现有原则）

代码中已确立的原则（必须保留）：

1. **触达诊断不落敏感字段**：engine-actions.js:94-95 注释明确——「Only adapter-owned codes, aggregate counts and an identity-evidence enum. Never log names, selectors, IDs, avatar URLs, messages or response bodies.」实现上只取计数白名单与证据枚举（engine-actions.js:96-105）。
2. **网络诊断路径脱敏**：action-receipts.js:130-138 `safePath` 只保留通用词（im/message/send 等），任意 slug/ID/编码值替换为 `:segment`；URL 校验拒绝带用户名/密码的地址（action-receipts.js:121-128）；**不读响应体**（action-receipts.js:176「No response body, error text or protocol payload is read」）；请求失败文本不落盘（action-receipts.js:184，注释「可含 URL」）。
3. **协议核验只落聚合计数**：dm-receipt-observer.js:104 `summary()` 仅 `{recognizedRequests, decodedResponses, ambiguous}`。
4. **代理凭据不落盘**：parseProxy 拆出 `server=协议://host:port`（不含 user:pass），engine.js:83-92、224 只记录 server。
5. **AI 日志不落评论原文**：AI_AUDIT 仅含 leadId、ruleVersion、批次计数、token 用量；输入哈希比对（engine-ai-tasks.js:7）在内存完成。

现状不一致点：

- engine-actions.js:61、490、595 三处把**用户昵称**写入账号日志（触达步骤/私信结果/线索处理异常）。账号日志文件因此含第三方用户昵称，与「不落库昵称」原则局部冲突。
- engine.js:224 记录本机 user-data 绝对路径（含用户目录名，低风险）。
- 实测 `dy-lead-app\data\logs` 中旧版遗留日志（2026-10-07）为**旧格式**：「AI 判断：{昵称} → 是（85分）{完整理由}」「关注成功：{昵称}（1/2）」——含昵称与判断理由，属历史数据，迁移时需一并处理。

### 1.6 实际落盘体量与编码

- 源码目录 `data\logs`：2 个文件共约 27KB（旧版遗留）。
- 安装版 `D:\华贸自媒体获客\data\logs`：6 个文件共约 0.21MB；单账号单日最大 97KB（system-2026-10-10.log 仅 947B）。**单日体量小，无需按大小轮转**。
- 编码 UTF-8 无 BOM：软件内读取正常；用 PowerShell 默认 GBK 或旧版记事本直接打开会乱码（实测）。

## 3. 重规划方案

### 3.1 日志分类与级别

**级别定义（5 级）**：

| 级别 | 用途 | 现有条目映射示例 |
|---|---|---|
| DEBUG | 高频过程细节，默认不显示 | `采集：捕获评论接口（新增 N 条…）`（engine.js:673 每轮一次，建议降级或聚合成一条） |
| INFO | 任务里程碑、正常结果 | `视频 XXX 采集完成`；`已确认抖音账号登录成功`；`浏览器模式已切换`；任务完成统计 |
| WARN | 可恢复问题、跳过、待核验 | `采集队列：${skip}`（engine-collection-tasks.js:76）；`触达名单跳过`；`私信已点击，回执尚未确认`（进入 taskState.status，也应落盘）；AI 重试/兜底 |
| ERROR | 失败与暂停 | `浏览器启动失败`；`采集停止：`；`任务暂停：`；`线索处理异常`；`request_failed`（致命类） |
| AUDIT（业务事件） | 不可篡改的业务结果审计 | `私信结果：…`；`关注结果`；`人工核验 … 操作者 …`；`AI_AUDIT …` |

**实现方式（最小改动）**：保持 `store.log(accountId, line)` 签名不动，新增 `store.logLv(accountId, level, module, line)`，落盘格式改为：

```
[2026-10-10 10:00:01][INFO][触达] 视频 7211... 采集完成：新增 65 条（总评论 113）
```

- 模块枚举固定：`账号/采集/触达/AI/授权/系统`。
- 兼容性：`formatAiLog` 的正则 `^(.*?)(?:AI_AUDIT)\s+(\{.*\})$`（app.js:1658）对新前缀仍可匹配（`.*?` 懒匹配吞掉时间+级别+模块），无需改动即可继续翻译 AI 日志。
- 旧格式文件保持原样（只读兼容），新写入统一新格式。

### 3.2 界面展示方案

**三个展示层，职责分开**：

1. **任务进度区（实时，已有，保持）**：taskState.status/detail + 进度条 + 6 步阶段流 + 当前用户 + 等待倒计时 + AI 预算。2.5s 轮询已有。**新增**：把 `taskState.errors[]`（engine-actions.js:594 已有数据）渲染为进度区下方的「本任务异常」列表（任务结束清空）——数据已在，缺的只是渲染。
2. **日志页（按需展开，改造）**：从「纯文本 + 账号筛选」升级为：
   - 筛选栏：账号（现有，含 system）+ **级别**（全部/仅 WARN+ERROR）+ **类型**（全部/账号/采集/触达/AI/授权/系统）+ **日期**（今天/近 3 天/近 7 天/近 30 天，需后端支持历史文件）+ 关键词（前端过滤即可）。
   - 行内着色：ERROR 红、WARN 黄、AUDIT 强调、DEBUG 灰且默认隐藏。
   - 数据获取：`/api/logs/{accountId}?date=YYYY-MM-DD&level=warn+&lines=200`；日志页可见时随现有 2.5s 轮询刷新（已有机制）。
   - 保留 AI_AUDIT 中文翻译（formatAiLog）。
3. **系统事件（可选页/开关，最小实现为日志页内开关）**：`system` 账号日志中 ERROR 级条目聚合视图（浏览器启动失败、任务暂停、授权失效），按时间倒序；「仅看错误」开关即可实现，不必新建页面。

**实时 vs 按需**：任务进度区实时（轮询，轻量）；日志页按需拉取 + 可见时自动刷新（现状已如此）；历史日志按需展开（date 参数）。不建议做 WebSocket 推送——轮询已满足 2.5s 粒度，改动收益不成比例。

### 3.3 文件落盘方案

**目录与命名（保持现状为主）**：

```
{DATA_DIR}/logs/
  {accountId}-{yyyy-MM-dd}.log        # 账号日志（accountId 经 safeId 白名单校验）
  system-{yyyy-MM-dd}.log             # 系统/AI/授权日志
```

- **轮转**：按天已有；单文件大小上限设为 2MB（写入前 `fs.statSync`，超限追加 `.{n}` 序号分片，`tailLog` 读最新分片）——实测单日峰值 97KB，此为防御性上限，属「建议」级。
- **保留策略（必须）**：新增 `cleanupLogs(retainDays)`，默认保留 **30 天**，服务启动时执行一次（server.js 启动流程或 store.js `ensureDirs` 后）；保留天数放入 `settings.logs.retainDays`（默认 30，可选 7/30/90），设置页加一项（可选）。删除只针对 `logs/` 目录内匹配 `^[\w-]{1,100}-\d{4}-\d{2}-\d{2}(\.\d+)?\.log$` 的文件，杜绝误删。
- **隐私脱敏要求（必须，统一现有原则）**：
  1. 保留并扩展现有原则（engine-actions.js:94-95）：**落盘白名单** = 操作结果、聚合计数、错误码、状态枚举、leadId/视频 ID、token 用量；**黑名单** = 昵称、选择器、响应体、消息正文、头像 URL、代理凭据、网络失败文本（可能含 URL）。
  2. **整改现状 3 处昵称落盘**：engine-actions.js:61/490/595 的 `${lead.nickname}` 改为 `线索 #${leadId}`（界面上的当前用户昵称显示不受影响，taskState.currentLead.nickname 仍在 app.js:391 展示）；`私信结果` 日志同样改 leadId。
  3. engine.js:224 的 user-data 绝对路径缩为 `data\chrome-profiles\{safeId}` 相对形式（可选，低风险）。
  4. **历史遗留日志**：`data\logs` 中旧版格式文件（含昵称+AI 理由）随保留策略自然过期，或在升级脚本中主动清空 `logs/`（建议后者，一次性）。
  5. AI_AUDIT 维持现状（无昵称/原文，仅 leadId + 计数）——已合规。
- **编码**：保持 UTF-8；在日志页加「下载当天日志」按钮（前端 Blob 下载，可选），并在 使用说明.md 注明「日志为 UTF-8 编码，用记事本打开乱码属正常，请在软件日志页查看」。不写 BOM（append 模式会重复 BOM）。
- **写失败可见性（建议）**：`log()` 返回写入结果计数，连续失败置 `taskState.auditWarning`（AI 已有该机制，engine-ai-tasks.js:39，扩展到全部日志）。
