# 列表界面重设计方案（作品采集历史 + AI 与线索）

版本：v1 草案（2026-10-09）
原则：**信息分层、先扫读后细读**——每行第一眼只看到最关键信息，细节按需展开，不再依赖横向滚动。

---

## 一、通用设计规范（两个列表统一）

### 1. 字体体系

| 用途 | 字号 | 字重 | 颜色 |
|---|---|---|---|
| 页面标题 | 20px | 600 | #1f2329 |
| 区块标题 | 15px | 600 | #1f2329 |
| 表格正文 | **13px**（当前 16px 过大，是"不舒服"主因） | 400 | #333a45 |
| 次要信息（时间/计数/链接） | 12px | 400 | #8a919c |
| 徽章文字 | 11px | 500 | 按语义色 |
| 等宽数据（作品ID/UID） | 12px monospace | 400 | #556070 |

### 2. 间距与密度

- 行高：紧凑模式 44px / 舒适模式 56px（提供切换按钮，默认舒适）
- 单元格内边距：10px 14px（当前 14px 16px 偏松）
- 表头：灰底 #f2f4f7、文字 12px、字母间距 +0.3px，**冻结吸顶**
- 斑马纹：隔行 #fafbfc（极淡），替代全白；hover 行 #f1f6ff

### 3. 视觉层级（每行三段式）

```
[状态色点]  主信息（昵称/描述，13px 深色，最多两行）
            副信息（时间·次数·ID，12px 灰色，一行）
[操作区]    按钮靠右对齐，图标化 + 文字，不换行
```

---

## 二、作品采集历史 —— 方案 A（推荐）：紧凑信息行

**放弃宽表格**，改为上下结构的"信息行"（列表行内两行文字）：

```
┌─────────────────────────────────────────────────────────┐
│ ●完整  亚马逊重启店铺 #激活店铺 #亚马逊申诉资金…（13px 两行截断，点击看全文）│
│       10-09 14:32 完成 · 采集 3 次 · video/7693378…（12px 灰）│
│                                        [＋加入队列] [删除] │
├─────────────────────────────────────────────────────────┤
│ ●部分  平台作品详情返回空描述（标题留空时的占位徽章）              │
│       10-09 10:05 中断（可续采） · 采集 1 次                 │
│                                        [＋加入队列] [删除] │
└─────────────────────────────────────────────────────────┘
```

要点：
- 状态色点：绿=完整 / 橙=部分 / 灰=未核验，替代整格"完整度"列
- 主信息=作品标题+正文摘要（两行截断，点击弹出全文，保留现有 showFieldDetail 逻辑）
- 副信息合并三列（时间/次数/ID），"原因"只在非完整时以橙色小字跟在副信息后
- 操作按钮右对齐，hover 才高亮，减少视觉噪音
- 历史列表高度放宽到 400px，仍在本页面板内

## 三、AI 与线索 —— 方案 A（推荐）：固定核心列 + 行内展开详情

**痛点**：12+ 字段横向滚动。**解法**：表格只保留 6 个核心列，其余字段放进"行内展开区"。

### 核心列（永远可见，无横向滚动）

| 列 | 内容 | 宽 |
|---|---|---|
| ☑ | 勾选 | 40px |
| 用户 | 昵称（13px 加粗）+ 属地/评论时间小字（12px 灰，两行合一） | 180px |
| 需求 | 评论内容摘要（13px 两行截断，点击查看全文） | 弹性 |
| AI | 是/否徽章 + 旧规则角标（徽章 11px） | 90px |
| 触达 | 状态徽章组合（已关注/已私信/待核验，最多2个） | 140px |
| 操作 | 三个图标按钮：🔍查看主页 ｜ 📋详情 ｜ 重判（hover 显示文字） | 120px |

### 行内展开区（点击行任意处或"详情"展开）

展开后在该行下方插入一个详情面板（背景 #f8fafc），**字段分组两列网格**展示：

```
┌─ 展开详情 ─────────────────────────────────────────────┐
│ 基础信息           │ 评论与作品                          │
│ UID 753908774532… │ 评论全文：…                         │
│ 抖音号 abc57346…  │ 触发词：怎么收费                     │
│ 主页链接 ↗        │ 作品描述：亚马逊重启店铺…（查看全文）   │
├────────────────────┼───────────────────────────────────┤
│ 触达记录           │ AI 判断                             │
│ 关注时间/结果      │ 判断：是（旧规则）· 理由：…           │
│ 私信时间/结果/次数 │ 粉丝数/关注数/属地（扩展字段在此）      │
└────────────────────────────────────────────────────────┘
```

- 原"显示更多数据字段"勾选项改为**决定展开面板里显示哪些扩展字段**（不再影响表格宽度）
- 状态徽章、核验按钮等现有功能全部保留，只是移入展开区
- 排序仍点击表头，排序字段下拉可选（核心列直接点，扩展字段在面板顶部小下拉）

### 备选：方案 B（改动最小）

保持现有动态列表格，仅做视觉优化（13px 字体、紧凑间距、斑马纹、冻结首列与表头、字段默认宽度收敛到 ≤200px）。**如果担心界面测试影响，先做 B 再演进到 A。**

## 四、对现有功能/测试的影响评估

- 两个方案都**保留全部现有 data-* 属性和 ID**（data-lead-id、data-lead-action、data-detail-lead 等），事件绑定逻辑不动
- `renderVideoHistory` / `renderLeads` 只改模板输出与 CSS，不动数据接口
- 现有 51 项界面测试若断言了旧 DOM 结构（如 th 数量），方案 A 需要同步更新测试断言；方案 B 基本不影响
- 建议落地顺序：**先 B（1 小时）快速改善观感 → 再 A（1~2 天）完成信息架构**

## 五、需要你拍板的点

1. 采用方案 A 还是 B？（我推荐：视觉先按 B 上，结构按 A 做）
2. 行密度默认"舒适"还是"紧凑"？
3. 线索表核心 6 列是否要调整（比如把"属地"放进核心列）？
