# 多账号分发触达 设计方案（v1 草案，2026-10-16）

## 一、问题与目标

**现状**：采集账号与触达账号绑定（名单生成 `selectedLeads(all, accountId)`、执行 `runTask` 校验 `lead.accountId === accountId`、联系观察 `saveContactObservation` 也要求同账号）。一个号每天安全私信只有几十条，但一次扫描 3 天内的可联系用户可能几百上千 → 名单跑不完，剩下的用户一直等。

**目标**：**采集归采集、触达归触达**——扫描一次形成"联系人池"，触达时按各账号当日配额自动分发，每个用户只由**一个账号**接触，多账号串行执行，一天消化完整个池子。

## 二、配额测算（为什么要多号分摊）

| 场景 | 数量 |
|---|---|
| 单账号每日安全私信（实测+平台限制） | 30~50 条（程序上限可设 150，但平台按小时/日风控，实际几十） |
| 3 天扫描积累的可联系用户（AI=是） | 按当前采集量估算 200~500 人 |
| 单号消化 300 人需要 | 6~10 天（且天天顶格跑，风控风险高） |
| **3 个号分摊（每号 30~50/天）** | **2~3 天** |
| **5 个号分摊** | **1~2 天** |

结论：**3~5 个执行号 + 分摊分配，是把扫描成果转化为触达的关键**。

## 三、总体架构

```
采集（任意号，现有流程不变）
  → AI 判断（不变）
  → 联系人池（按 contactKey=业务|uid 全业务唯一，现有 workflow.historyOf 已跨账号合并）
  → 【新增】分配层：生成分配方案 {uid → 执行账号、动作(关注/私信)}
  → 【新增】按账号拆分名单 → 逐账号复用现有「预检查 → 执行」流程（串行）
  → 每账号独立节奏（30s 用户间隔 + 每 N 条强制休息 + 每日上限）
```

## 四、分配算法

### 4.1 候选过滤（复用现有规则）
AI=是（当前规则有效）或人工批准；排除作者、已回复、不再联系、待核验；遵守重复私信间隔（`dm.repeat.intervalDays`）。

### 4.2 排序
评论时间新→旧（3 天内优先），同视频用户尽量分散。

### 4.3 账号选择（逐用户贪心）
按以下优先级给每个用户挑账号：
1. **剩余额度最多**：当日 dm/follow 剩余额度（`workflow.getQuotas`）多的优先
2. **当日已用最少**：额度相同看已用量
3. **健康**：账号登录状态正常（登录待确认/受限的跳过）
4. **同视频错峰**：该视频已分配给这个账号的用户数最少（防"一个号盯着一个视频的人狂发"）
5. 所有账号都无额度 → 该用户进入"待分配"列表，显示"明天继续"

### 4.4 分配锁（防双发）
分配结果落库 `contact-allocation.json`：
```json
{ "uid": "...", "accountId": "3", "kind": "dm", "plannedAt": "...", "consumed": false }
```
- 预检查/执行时检查：uid 已有**未消费**分配且属于其他账号 → 跳过（防止两个账号同时联系同一人）
- 执行成功/失败后置 `consumed: true`；重复私信间隔到期后可再次分配（可换账号）

## 六、执行与节奏

- **串行执行**：当前引擎全局单任务，逐账号依次跑（账号间切换间隔建议 60~180 秒）
- 每账号内沿用现有节奏：用户间隔 30s±40%、每 N 条强制休息、每日上限、连续异常暂停
- 每账号独立代理（已有能力）——多号分摊后这是**必须配置项**，同 IP 多号触达=自找封号
- 停止按钮全局有效；某账号暂停/失败 → 记录并跳到下一账号，全部跑完汇总

```
└─ 完成汇总：覆盖 103 人｜成功 95｜待核验 4｜失败 4｜剩余待分配 42
```

## 八、分阶段落地

| 阶段 | 内容 | 工期 |
|---|---|---|
| P1（建议先做） | 分配方案生成+预览（手动确认每账号名单），执行仍走现有单账号流程 | 1~2 天 |
| P2 | 逐账号串行自动执行 + 分配锁防双发 | 2~3 天 |
| P3 | 智能分配优化（同视频错峰、失败账号降权、健康度加权）+ 待分配队列管理 | 视效果再定 |

## 九、风险提示

1. **同一用户 7 天内只允许一个账号接触**（分配锁 + repeat 规则），否则被平台判定协同骚扰
2. 多账号必须**一账号一 IP**（代理），否则分摊变成集中暴露
3. 分摊放大的是"总量"，不是"单号频率"——每号仍守每小时安全线，别把 150 上限当真用
4. 私信话术建议后续接 AI 个性化（之前讨论过），多号跑固定模板更容易被判营销号
